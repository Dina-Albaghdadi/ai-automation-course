# U5 Project — XYZ Real Estate AI Agent

## 1. Project Overview

في هذا المشروع، ستبنين **AI Agent** لشركة XYZ Real Estate باستخدام **n8n**.

يستقبل الـ Agent رسائل العملاء عبر Telegram، ويفهم احتياجاتهم العقارية، ويجمع المعلومات المطلوبة منهم تدريجيًا، ويتذكر المعلومات التي قدموها خلال المحادثة، ثم يعرض ملخصًا نهائيًا للتأكد من صحته قبل حفظه في Google Sheets.

المشروع ليس مجرد Chatbot يطرح أسئلة متتابعة؛ بل نظام يستخدم الذكاء الاصطناعي لفهم المعلومات، وتحديد الخطوة التالية، واتخاذ قرار بشأن استخدام أداة خارجية ضمن شروط محددة.

**الفكرة الأساسية:**

بناء AI Agent يعرف ماذا يفعل، ومتى يفعله، ومتى يجب أن ينتظر تأكيد المستخدم قبل تنفيذ أي إجراء.

---

## 2. Business Scenario

تستقبل شركة XYZ Real Estate طلبات من عملاء يرغبون في شراء عقارات أو استئجارها.

يحتاج فريق الشركة إلى جمع معلومات أساسية عن كل عميل لفهم احتياجاته ومتابعته.

بدلًا من جمع المعلومات يدويًا، سيتولى الـ Agent إدارة المحادثة مع العميل، وتحديد المعلومات الناقصة، والتحقق من الإجابات، ثم حفظ البيانات بعد موافقة العميل على الملخص النهائي.

---

## 3. Project Requirements

يجب أن يكون النظام قادرًا على تنفيذ المهام التالية:

1. استقبال رسائل العملاء عبر Telegram.
2. الترحيب بالعميل وبدء المحادثة.
3. فهم المعلومات التي يقدمها العميل، حتى لو ذكر عدة معلومات في رسالة واحدة.
4. الاحتفاظ بسياق المحادثة للاستفادة من الإجابات السابقة.
5. تحديد المعلومات الناقصة وطرح الأسئلة اللازمة فقط.
6. تطبيق قواعد العمل والتحقق من القيم المطلوبة.
7. عرض ملخص نهائي للعميل وطلب تأكيده.
8. حفظ البيانات في Google Sheets بعد التأكيد الصريح فقط.
9. التحقق من نتيجة الحفظ قبل إبلاغ العميل بنجاح العملية.

## 4. Customer Information

يجب على الـ Agent جمع الحقول التالية:

| Field | Description | Allowed Values / Requirements |
|---|---|---|
| Property type | نوع العقار | Apartment, Villa, Commercial |
| Buy/Rent | نوع الطلب | Buy, Rent |
| New/Resale | حالة العقار المطلوب شراؤه | New, Resale, Not Applicable |
| First Ourcase | إجابة العميل عن هذا الحقل | Yes, No, Not Applicable |
| Timeline | الإطار الزمني المتوقع | Immediately, Within 1 month, 1–3 months, 3–6 months, 6+ months |
| Budget | الميزانية | إحدى الفئات المحددة أدناه |
| Name | اسم العميل | يقدمه العميل |
| Email | البريد الإلكتروني | يجب أن يكون بصيغة صحيحة |
| Phone Number | رقم الهاتف | يقدمه العميل |

### Budget Categories

يجب تصنيف الميزانية ضمن إحدى الفئات التالية:

- `Below $200,000`
- `$200,000 to below $400,000`
- `$400,000 to below $700,000`
- `$700,000 to $1,000,000`
- `Above $1,000,000`

تُطبَّق الحدود كما يلي:

| Budget | Value |
|---|---|
| Less than $200,000 | Below $200,000 |
| $200,000 to less than $400,000 | $200,000 to below $400,000 |
| $400,000 to less than $700,000 | $400,000 to below $700,000 |
| $700,000 to $1,000,000 | $700,000 to $1,000,000 |
| More than $1,000,000 | Above $1,000,000 |

إذا كانت إجابة العميل غير واضحة، يجب على الـ Agent طلب التوضيح بدلًا من التخمين.

### Conditional Rules

إذا كان طلب العميل `Buy`، فيجب جمع معلومات `New/Resale` و`First Ourcase`.

أما إذا كان طلبه `Rent`، فيجب:

- عدم طرح أسئلة عن `New/Resale`.
- عدم طرح أسئلة عن `First Ourcase`.
- تعيين قيمة الحقلين إلى `Not Applicable`.

يجب تطبيق هذه القواعد قبل إعداد الملخص النهائي وحفظ البيانات.

## 5. Workflow Architecture

ابني الـ Workflow في n8n باستخدام المكونات التالية:

### Main Workflow

```text
Telegram Trigger
       |
       v
    AI Agent
       |
       v
Telegram Send Message
```

### AI Agent Components

وصّلي المكونات التالية بالـ AI Agent من خلال المنافذ المخصصة لها:

- **OpenRouter Chat Model:** نموذج اللغة الذي يستخدمه الـ Agent لفهم الرسائل وصياغة الردود.
- **Simple Memory:** الاحتفاظ بسياق المحادثة بين الرسائل.
- **Google Sheets Tool:** إضافة بيانات العميل إلى جدول البيانات بعد استيفاء شروط الحفظ.

### Component Responsibilities

| Component | Responsibility |
|---|---|
| Telegram Trigger | استقبال رسائل العميل |
| AI Agent | فهم الرسائل، وجمع المعلومات، وتحديد الخطوة التالية |
| OpenRouter Chat Model | معالجة اللغة وتوليد الردود |
| Simple Memory | الاحتفاظ بسياق المحادثة |
| Google Sheets Tool | حفظ بيانات العميل |
| Telegram Send Message | إرسال رد الـ Agent إلى العميل |

يجب إعداد `Simple Memory` باستخدام Session ID مناسب وثابت لكل محادثة، واختبار أن معلومات العملاء لا تختلط بين الجلسات المختلفة.

## 6. Required Agent Behavior

يجب أن يتبع الـ Agent السلوك التالي:

### Step 1 — Welcome the Customer

ابدئي المحادثة برسالة الترحيب التالية:

> Hello and welcome to XYZ Real Estate! 🏡
>
> We're delighted to help you find the right property for your needs. Whether you're looking to buy or rent, I'm here to guide you through the process and understand what you're looking for.
>
> To get started, are you looking to buy a property or rent one?

### Step 2 — Collect Information

يجب على الـ Agent:

- فهم المعلومات التي يقدمها العميل.
- الاحتفاظ بالإجابات السابقة والاستفادة منها.
- قبول تقديم المعلومات بأي ترتيب.
- طرح أسئلة عن الحقول الناقصة فقط.
- طلب التوضيح عند وجود إجابات غامضة.
- عدم اختراع معلومات لم يقدمها العميل.

### Step 3 — Validate Information

قبل إعداد الملخص، يجب التأكد من أن المعلومات المطلوبة مكتملة ومتوافقة مع قواعد المشروع.

على سبيل المثال:

- إذا كان البريد الإلكتروني غير صالح، يطلب الـ Agent تصحيحه.
- إذا كانت الميزانية غير واضحة، يطلب تحديدها.
- إذا كان الطلب `Rent`، يضع `Not Applicable` في الحقلين غير المنطبقين.
- إذا غيّر العميل إجابته، يحدّث المعلومات وفقًا لذلك.

### Step 4 — Confirm Before Saving

عندما تكتمل جميع الحقول المطلوبة، يعرض الـ Agent ملخصًا للعميل، ثم يطلب تأكيده.

يجب أن يحتوي الملخص على الحقول التسعة:

```text
Property type:
Buy/Rent:
New/Resale:
First Ourcase:
Timeline:
Budget:
Name:
Email:
Phone Number:
```

يجب ملء الحقول بالقيم الفعلية التي قدمها العميل، مع تطبيق القواعد الشرطية.

إذا صحح العميل أي معلومة، يجب تحديث الملخص وطلب التأكيد مجددًا.

**لا يجوز حفظ البيانات لمجرد اكتمالها؛ بل يجب الحصول على تأكيد صريح من العميل على المعلومات النهائية.**

### Step 5 — Save the Confirmed Information

بعد اكتمال المعلومات والتحقق منها والحصول على تأكيد العميل، يستخدم الـ Agent أداة Google Sheets لإضافة البيانات.

يجب أن تكون البيانات المحفوظة مطابقة للملخص الذي وافق عليه العميل.

### Step 6 — Verify the Result

بعد محاولة الحفظ، يجب التحقق من نتيجة تنفيذ Google Sheets Tool.

- إذا نجح الحفظ، يمكن إبلاغ العميل بنجاح العملية.
- إذا فشل الحفظ، يجب إبلاغ العميل بأن العملية لم تنجح، دون الادعاء بأن البيانات حُفظت.

## 8. Practical Testing

بعد بناء النظام، نفّذي الاختبارات التالية للتحقق من سلوكه الفعلي:

| Test | Scenario | Expected Result |
|---|---|---|
| 1 | يبدأ عميل محادثة جديدة | يستقبل رسالة الترحيب ويبدأ جمع المعلومات |
| 2 | يقدم العميل عدة معلومات في رسالة واحدة | يستفيد الـ Agent من جميع المعلومات الواضحة دون تكرار الأسئلة |
| 3 | يقدم العميل معلومات غير مكتملة | يسأل عن المعلومات الناقصة فقط |
| 4 | يقدم العميل إجابة غامضة | يطلب التوضيح بدلًا من التخمين |
| 5 | يريد العميل استئجار عقار | يضع `Not Applicable` في الحقلين غير المنطبقين ولا يسأل عنهما |
| 6 | يرسل العميل عدة رسائل متتابعة | يحتفظ النظام بسياق المحادثة |
| 7 | يصحح العميل إحدى إجاباته | يحدّث الـ Agent المعلومات ويعرض ملخصًا جديدًا |
| 8 | تكتمل المعلومات دون تأكيد العميل | لا تُحفظ البيانات |
| 9 | يؤكد العميل صحة الملخص | تُحفظ البيانات الصحيحة في الأعمدة المحددة |
| 10 | تفشل أداة Google Sheets | لا يدّعي الـ Agent نجاح الحفظ |
| 11 | يُعاد إرسال التأكيد أو معالجة الطلب نفسه | اختبري عدم إضافة صف مكرر للطلب المكتمل نفسه |
| 12 | يتحدث عميلان مختلفان مع النظام | تبقى معلومات كل عميل منفصلة |

**مهم:** لا يكفي أن يقول الـ Agent إنه لم يحفظ البيانات قبل التأكيد. تحققي من سجل تنفيذ n8n ومن محتوى Google Sheets للتأكد من عدم حدوث الحفظ فعلًا.

إذا أمكن استدعاء Google Sheets Tool قبل التأكيد، عدّلي تصميم الـ Workflow وأضيفي ضوابط تنفيذ مناسبة لمنع ذلك.

يجب أن يتضمن التسليم النهائي:

1. **n8n Workflow:** النظام كاملًا مع المكونات المطلوبة.

## Project Success Criteria

يُعتبر المشروع ناجحًا عندما يستطيع الـ Agent:

- فهم رسائل العميل وجمع المعلومات المطلوبة.
- الاحتفاظ بسياق المحادثة والاستفادة منه.
- تحديد المعلومات الناقصة وتطبيق قواعد العمل.
- طلب تأكيد العميل قبل حفظ البيانات.
- حفظ المعلومات الصحيحة في Google Sheets.
- التحقق من نتيجة الحفظ قبل إبلاغ العميل بنجاح العملية.

**The goal is not simply to connect AI to a tool. The goal is to build an AI Agent that makes appropriate decisions and executes actions under controlled conditions.**
