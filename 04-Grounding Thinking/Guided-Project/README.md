# TECHFIX — AI Computer Troubleshooting Assistant
## مساعد ذكي لاستكشاف مشكلات الحاسوب

---

## 1. نبذة عن المشروع

**TECHFIX** هو مساعد ذكي باللغة العربية يساعد المستخدمين على استكشاف مشكلات الحاسوب الشائعة، وفهم أسبابها المحتملة، والوصول إلى إرشادات أولية واضحة وآمنة.

بُني المشروع باستخدام منصة Dify، ويعتمد على قاعدة معرفة متخصصة تحتوي على معلومات تقنية وإرشادات لاستكشاف المشكلات وإصلاحها.

عندما يصف المستخدم مشكلة، يسترجع النظام معلومات ذات صلة من قاعدة المعرفة، ثم يستخدم النموذج اللغوي هذه المعلومات لصياغة إجابة مناسبة.

لا يهدف TECHFIX إلى تقديم إجابة عن كل سؤال، بل إلى تقديم إرشادات تستند إلى المعلومات المتاحة، وطلب تفاصيل إضافية عند الحاجة، والتصريح بعدم كفاية المعرفة عندما لا تتوفر معلومات مناسبة.

يمثل المشروع تطبيقًا عمليًا لبناء مساعد ذكي يعتمد على المعرفة المنظمة، مع الاهتمام بجودة الاسترجاع، ودقة الإجابات، وحدود المساعدة.

---

## 2. المشكلة التي يعالجها المشروع

يواجه كثير من المستخدمين صعوبة في التعامل مع مشكلات الحاسوب، خصوصًا عندما تكون الأعراض غير واضحة أو عندما تكون الإرشادات التقنية المتاحة معقدة أو غير مناسبة لحالتهم.

من أمثلة هذه المشكلات:

- بطء الحاسوب.
- امتلاء مساحة التخزين.
- تعذّر الاتصال بشبكة Wi-Fi أو الإنترنت.
- الحاجة إلى إرشادات تقنية واضحة ومراعية للسلامة.

يسعى TECHFIX إلى تسهيل الوصول إلى المعرفة التقنية وتقديمها بطريقة تساعد المستخدم على فهم المشكلة والبدء بخطوات مناسبة للتعامل معها.

### القيمة التي يقدمها المشروع

- تقديم إرشادات تقنية باللغة العربية.
- تنظيم المعرفة في مستندات متخصصة.
- ربط الإجابات بمعلومات مسترجعة من قاعدة المعرفة.
- طلب تفاصيل إضافية عندما يكون وصف المشكلة غير كافٍ.
- تقليل الإجابات العامة التي لا تعالج المشكلة الفعلية.
- توضيح حدود المساعدة عندما لا تتوفر معلومات مناسبة.
- تنبيه المستخدم إلى الحالات التي تستدعي تدخل فني مختص.

## 3. نطاق المشروع وحدوده

يركز الإصدار الأول من TECHFIX على أربعة محاور رئيسية:

| المحور | نطاق المعرفة |
|---|---|
| بطء الحاسوب | استكشاف مشكلات الأداء والأسباب المحتملة للبطء. |
| مساحة التخزين | فهم أسباب امتلاء مساحة التخزين والتعامل معها. |
| اتصال الإنترنت | استكشاف مشكلات الاتصال بالشبكة والإنترنت. |
| السلامة وحدود المساعدة | تحديد الإجراءات الآمنة، والتحذيرات، والحالات التي تتطلب مختصًا. |

تعتمد قدرة المساعد على تقديم الحلول على مدى تغطية هذه الموضوعات في قاعدة المعرفة.

### حدود المساعد

TECHFIX نموذج أولي للإرشاد التقني، وليس أداة تفحص الحاسوب فعليًا أو تنفذ الإصلاحات مباشرة.

يلتزم المساعد بالمبادئ التالية:

- عدم اختلاق معلومات أو خطوات حل غير مدعومة.
- عدم تأكيد سبب العطل دون معلومات كافية.
- طلب تفاصيل إضافية عندما تكون ضرورية.
- توضيح عدم كفاية المعرفة عندما لا تتوفر معلومات مناسبة.
- تجنب الإرشادات التي قد تؤدي إلى فقدان البيانات أو الإضرار بالنظام.
- توضيح التحذيرات قبل اقتراح الإجراءات الحساسة.
- توجيه المستخدم إلى فني مختص عندما تتجاوز المشكلة نطاق المساعدة المتاحة.

وجود معلومات في قاعدة المعرفة لا يضمن وحده صحة الإجابة النهائية؛ لذلك يجب اختبار الاسترجاع والإجابة بصورة منفصلة.

## 4. تطبيق مفاهيم الوحدة الرابعة

يوضح TECHFIX كيفية تطبيق مفاهيم بناء مساعد يعتمد على المعرفة ضمن مشروع عملي واحد.

| المفهوم | تطبيقه في TECHFIX |
|---|---|
| Problem | صعوبة الوصول إلى إرشادات تقنية واضحة وآمنة باللغة العربية. |
| Desired Outcome | مساعدة المستخدم على فهم المشكلة وتحديد خطوات أولية مناسبة. |
| Requirements | استقبال وصف المشكلة، واسترجاع المعرفة، وتوليد إجابة واضحة وآمنة. |
| Assistant Instructions | تحديد دور المساعد ونطاقه وطريقة استجابته. |
| Knowledge Sources | استخدام مصادر تقنية مناسبة وموثوقة. |
| Knowledge Base | تنظيم المعرفة في أربعة مستندات متخصصة. |
| Document Processing | تجهيز المستندات ومعالجتها لتصبح مناسبة للاسترجاع. |
| Chunking | تقسيم المحتوى إلى أجزاء تحافظ على المعنى والسياق. |
| Metadata | تنظيم المستندات باستخدام بيانات وصفية عند الحاجة. |
| RAG | استخدام المعلومات المسترجعة من قاعدة المعرفة عند توليد الإجابات. |
| Grounding | التحقق من مدى دعم المعلومات المسترجعة للادعاءات الواردة في الإجابة. |
| Knowledge Retrieval | استرجاع المقاطع المرتبطة بسؤال المستخدم. |
| Retrieval Quality | تقييم مدى ملاءمة المعلومات المسترجعة وكفايتها. |
| Prompt Engineering | تحديد سلوك المساعد وقواعد الإجابة وحدودها. |
| Testing | اختبار الاسترجاع والإجابات باستخدام سيناريوهات متنوعة. |
| Failure Analysis | تحديد موضع الخلل المحتمل عند ظهور إجابة غير مناسبة. |
| Iteration | تحسين النظام بناءً على نتائج الاختبارات وإعادة تقييمه. |
| Safety | تجنب الإرشادات غير الآمنة والالتزام بحدود المساعدة. |

## 5. التقنيات المستخدمة

| التقنية | دورها في المشروع |
|---|---|
| Dify | بناء تطبيق الذكاء الاصطناعي وإدارة مكوناته. |
| Knowledge Base | تخزين مستندات المعرفة التي يعتمد عليها المساعد. |

| System Prompt | تحديد دور المساعد وسلوكه وقواعد الإجابة. |
| Markdown | كتابة مستندات المعرفة وتوثيق المشروع. |
| GitHub | تنظيم ملفات المشروع وتوثيق العمل. |

تختلف بعض الإعدادات والخصائص المتاحة باختلاف إصدار Dify ونوع التطبيق المستخدم.

## 6. بنية النظام

يعتمد مسار العمل في TECHFIX على أربع مراحل رئيسية:

```text
User Question
      |
      v
     Start
      |
      v
Knowledge Retrieval
      |
      v
      LLM
      |
      v
    Answer
```

### مكونات النظام

**1. Start**

استقبال سؤال المستخدم ووصف المشكلة.

**2. Knowledge Retrieval**

البحث في قاعدة المعرفة عن المعلومات المرتبطة بالمشكلة واسترجاع النتائج المناسبة.

**3. LLM**

استخدام السؤال والتعليمات والمعلومات المسترجعة لصياغة إجابة مناسبة، مع مراعاة حدود المعرفة والسلامة.

**4. Answer**

عرض الإجابة النهائية للمستخدم.

يعتمد أداء النظام على جودة مصادر المعرفة، وملاءمة النتائج المسترجعة، وكفاية السياق المتاح، وطريقة استخدام النموذج للمعلومات.

ولا يعني استرجاع معلومات مرتبطة بالمشكلة بالضرورة أن الإجابة النهائية ستكون صحيحة أو مكتملة؛ لذلك يتضمن المشروع مرحلة مستقلة لتقييم الأداء وتحسينه.

## 7. قاعدة المعرفة

تتكون قاعدة معرفة TECHFIX من أربعة مستندات، يختص كل منها بمحور محدد.

```text
knowledge-base/
│
├── 01-بطء-الحاسوب.md
├── 02-مساحة-التخزين.md
├── 03-اتصال-الإنترنت.md
└── 04-السلامة-وحدود-المساعدة.md
```

### محتوى المستندات

| الملف | المحتوى |
|---|---|
| `01-بطء-الحاسوب.md` | معلومات عن مشكلات بطء الحاسوب، والأسباب المحتملة، وخطوات الاستكشاف المناسبة. |
| `02-مساحة-التخزين.md` | معلومات عن امتلاء مساحة التخزين، وطرق التحقق من المساحة، والإجراءات المناسبة لتحريرها. |
| `03-اتصال-الإنترنت.md` | معلومات عن مشكلات الاتصال بالشبكة والإنترنت، وأسئلة التشخيص الأولي، وخطوات استكشاف المشكلة. |
| `04-السلامة-وحدود-المساعدة.md` | قواعد السلامة، والتحذيرات، وحدود المساعد، والحالات التي تستدعي تدخل فني مختص. |

### متطلبات قاعدة المعرفة

يجب أن تكون المستندات:

- مرتبطة بنطاق المشروع.
- واضحة ومنظمة.
- مستندة إلى معلومات موثوقة.
- خالية من التكرار غير الضروري.
- مكتوبة بطريقة تساعد على استرجاع الأجزاء المناسبة.
- محتوية على التحذيرات والشروط المهمة.
- مرتبطة بالمصادر الأصلية عندما تُستخدم مراجع خارجية.

يجب أيضًا التحقق من سلامة النصوص بعد رفعها إلى Dify، ومراجعة الأجزاء الناتجة عن معالجة المستندات وتقسيمها.

## 8. الاختبارات الأولية

اختُبر النظام مبدئيًا باستخدام أسئلة تتعلق ببطء الحاسوب، ومساحة التخزين، والاتصال بالإنترنت، وطلبات تتطلب الانتباه إلى حدود المساعدة والسلامة.

أظهرت الاختبارات الأولية أن المساعد يستطيع تقديم إرشادات مفيدة لبعض الحالات، لكنه لا يقدم المستوى نفسه من التفصيل والكفاية في جميع الإجابات.

فعلى سبيل المثال، كانت إحدى إجابات مشكلة الاتصال بالإنترنت محدودة، رغم استرجاع نتائج من ملف المعرفة المرتبط بالموضوع.

توضح هذه النتيجة أن وجود معلومات ذات صلة في النتائج المسترجعة لا يضمن وحده أن يستخدمها النموذج بصورة كافية في الإجابة النهائية.

### ما الذي نتعلمه من الاختبارات؟

يجب تقييم مرحلتين منفصلتين:

| مجال التقييم | السؤال الأساسي |
|---|---|
| Retrieval Quality | هل استرجع النظام المعلومات المناسبة والكافية للمشكلة؟ |
| Answer Quality | هل استخدم النموذج المعلومات بصورة صحيحة، وقدم إجابة واضحة ومتكاملة وآمنة؟ |

### مجالات التقييم

- **Relevance:** مدى ارتباط النتائج بالسؤال.
- **Correctness:** صحة المعلومات والخطوات المقدمة.
- **Groundedness:** مدى دعم المعلومات المسترجعة للادعاءات الواردة في الإجابة.
- **Completeness:** مدى اكتمال الإجابة بالنسبة إلى الحالة.
- **Clarity:** وضوح الخطوات وترتيبها.
- **Safety:** مدى الالتزام بحدود السلامة.
- **Uncertainty Handling:** التعامل المناسب مع نقص المعلومات.

هذه النتائج أولية، ولا تمثل قياسًا شاملًا لأداء النظام. يحتاج تقييم الجودة إلى مجموعة اختبارات منظمة ونتائج موثقة.

## 9. خطة الاختبار والتحسين

سيتم تطوير جودة TECHFIX عبر اختبار حالات استخدام متنوعة وتحليل النتائج.

### أنواع الاختبارات

| نوع الاختبار | الغرض |
|---|---|
| Direct Questions | اختبار الأسئلة المباشرة التي تغطيها قاعدة المعرفة. |
| Paraphrased Questions | اختبار الأسئلة التي تصف المشكلة نفسها بصياغات مختلفة. |
| Missing Knowledge | اختبار الحالات التي لا تغطيها قاعدة المعرفة. |
| Incomplete Questions | اختبار الحالات التي تحتاج إلى معلومات إضافية. |
| Out-of-Scope Questions | اختبار التزام المساعد بنطاقه. |
| Safety-Related Questions | اختبار التعامل مع الطلبات التي قد تؤدي إلى إجراءات غير آمنة. |

### دورة التحسين

```text
Test
  |
  v
Review Retrieved Results
  |
  v
Evaluate Final Answer
  |
  v
Identify Failure Type
  |
  v
Apply Improvement
  |
  v
Retest
```

عند ظهور إجابة غير مناسبة، يجب تحديد السبب المحتمل قبل تعديل النظام.

قد يكون الخلل في محتوى المعرفة، أو في استرجاع المعلومات، أو في السياق المسترجع، أو في طريقة توليد الإجابة.

بعد تنفيذ أي تحسين مهم، يجب إعادة اختبار الحالة نفسها، ثم فحص حالات أخرى للتأكد من أن التغيير لم يؤثر سلبًا في جودة النظام.

### وظيفة الملفات والمجلدات

#### `README.md`

الملف الرئيسي الذي يقدم المشروع، ويشرح المشكلة التي يعالجها، ونطاقه، والتقنيات المستخدمة، وبنية النظام، وقاعدة المعرفة، والاختبارات، وهيكلية المستودع.

#### `01-دليل-التطبيق-العملي.md`

#### `02-تعليمات-النموذج.md`

يوثق التعليمات المستخدمة لتحديد دور المساعد، ونطاقه، وطريقة استخدام المعلومات المسترجعة، وشكل الإجابات، والتعامل مع نقص المعرفة، وحدود السلامة.

#### `knowledge-base/`

يحتوي على مستندات المعرفة الأربعة التي يستخدمها TECHFIX.

#### `screenshot/`

يحتوي على صور فعلية توثق إعداد التطبيق، وتجهيز قاعدة المعرفة، وإعدادات الاسترجاع، ونتائج الاختبارات.

أسماء الصور في الهيكل أمثلة تنظيمية؛ تُستبدل بها أسماء لقطات الشاشة الفعلية عند إضافتها.

## 11. معايير نجاح المشروع

يُقيّم TECHFIX بناءً على قدرته على:

- استرجاع معلومات مناسبة من قاعدة المعرفة.
- تقديم إجابات مرتبطة بالمشكلة المطروحة.
- الحفاظ على دقة المعلومات المنقولة من المصادر.
- استخدام المعلومات المسترجعة بطريقة مناسبة.
- طلب تفاصيل إضافية عندما يكون وصف المشكلة غير كافٍ.
- التصريح بحدود المعرفة عند عدم توفر معلومات مناسبة.
- تقديم خطوات واضحة ومراعية للسلامة.
- التعامل المناسب مع الأسئلة التي تقع خارج نطاقه.
- إظهار تحسن يمكن التحقق منه بعد تنفيذ التعديلات.

لا يعني نجاح المشروع أن يجيب المساعد عن جميع الأسئلة، بل أن يتعامل مع كل حالة وفق المعلومات المتاحة وحدود النظام.

## 12. النتيجة النهائية

يمثل TECHFIX تطبيقًا عمليًا لبناء مساعد ذكي يعتمد على قاعدة معرفة متخصصة لتقديم إرشادات تقنية باللغة العربية.

يجمع المشروع بين إعداد المساعد، وتنظيم المعرفة، وربطها بآلية الاسترجاع، ومراجعة جودة النتائج، واختبار الإجابات، وتحليل الإخفاقات، وتحسين النظام بناءً على النتائج الفعلية.

**المبدأ الأساسي للمشروع:**

لا يكفي أن يولّد النظام إجابة؛ بل يجب تقييم المعلومات التي استند إليها، ومدى ملاءمتها للمشكلة، وصحة الإجابة واكتمالها، وحدود المساعدة التي يقدمها.
