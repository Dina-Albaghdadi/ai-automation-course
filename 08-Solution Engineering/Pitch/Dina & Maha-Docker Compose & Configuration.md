## 1️⃣ ملاحظات البحث (Research Notes)

**📄 ما وظيفة ملف `compose.yaml`؟**
ملف `compose.yaml` (أو `docker-compose.yml`) هو الملف اللي بيوصف فيه كل تطبيق الـ containers اللي بدنا نشغلها مع بعض، بدل ما نشغل كل container لحاله يدويًا. هو ملف YAML واحد بيعرّف فيه: شو الـ Images المستخدمة، كيف بتتواصل الـ Containers مع بعض، وين بتنخزن البيانات بشكل دائم (Volumes)، وشو الإعدادات (Environment Variables) اللي بدها توصل لكل Container. بأمر واحد (`docker compose up -d`) بينبني ويشتغل كل اللي موصوف بالملف، وبأمر واحد كمان (`docker compose down`) بينوقف وينشال.

**⚙️ كيف يحدد Docker Compose الخدمات والإعدادات والمنافذ والتخزين؟**
- **Services (الخدمات)**: كل Container (زي n8n أو قاعدة بيانات أو Reverse Proxy مثل Traefik) بينكتب تحت قسم `services`، وبينحدد فيه الـ Image المستخدم وكل إعداداته الخاصة.
- **Ports (المنافذ)**: بتحدد بصيغة `host:container` (مثلاً `5678:5678`)، يعني أي منفذ على جهاز الخادم (Host) بينوصل لأي منفذ جوا الـ Container. في مثال n8n الرسمي، منفذ n8n بينربط بس على `127.0.0.1` (يعني داخليًا فقط)، وبيصير الوصول من بره عن طريق Traefik اللي فاتح منفذي 80 و443.
- **Volumes (التخزين)**: بتحدد مكان تخزين دائم للبيانات، بحيث لو انحذف الـ Container وانعمل من جديد، البيانات ما بتضيع. بمثال n8n في Volume اسمه `n8n_data` بيتخزن فيه قاعدة بيانات n8n ومفتاح التشفير بمسار `/home/node/.n8n`.

**🔑 ما وظيفة Environment Variables؟**
هي القيم اللي بتنمرر للـ Container وقت التشغيل عشان تتحكم بسلوكه من غير ما نعدّل كود أو صورة الـ Image نفسها — متل العنوان العام للتطبيق، المنفذ الداخلي، نوع البروتوكول (http/https)، أو المنطقة الزمنية. بمثال n8n في متغيرات زي `N8N_HOST`، `N8N_PORT`، `N8N_PROTOCOL`، `GENERIC_TIMEZONE`، و`N8N_WEBHOOK_URL`. هاي الطريقة بتخلي نفس الـ Image قابل لإعادة الاستخدام بأي بيئة (تطوير، اختبار، إنتاج) بس بتغيير القيم، من غير ما نلمس الكود.

**🆚 ما الفرق بين تشغيل Container منفردًا وإدارة التطبيق باستخدام Docker Compose؟**
لما نشغل Container واحد بأمر `docker run`، لازم نكتب كل إعداداته (المنافذ، الـ Volumes، المتغيرات) كـ flags بالأمر نفسه، وإذا التطبيق محتاج أكتر من Container (مثلاً n8n + Traefik للـ HTTPS) لازم نشغّل كل وحدة لحالها ونربطهم يدويًا بشبكة مشتركة. أما Docker Compose فبيوصف كل الـ Containers المرتبطة ببعض (Services) بملف واحد، بيحدد فيه العلاقات والترتيب بينهم (مثلاً Traefik لازم يشتغل قبل ما ن8n يستقبل طلبات)، وبيديرهم كوحدة واحدة بأوامر بسيطة (`up`, `down`, `logs`, `ps`). هاد بيخلي الإعداد قابل للتكرار ومشاركته (ينحط على Git مثلاً) بدل ما يضل بس بذاكرة الشخص اللي شغّله.

**🚀 لماذا يُستخدم Docker Compose في نشر n8n على الخوادم؟**
- **تكرار موثوق**: نفس ملف الـ Compose بيقدر يشغّل نفس البيئة بالضبط على أي خادم، من غير فروقات بين بيئة التطوير والإنتاج.
- **إدارة أسهل لعدة خدمات مع بعض**: نشر n8n بشكل احترافي عادة بيحتاج أكتر من Container (n8n نفسه + Traefik لإدارة شهادات HTTPS تلقائيًا عبر Let's Encrypt)، و Compose بيربطهم بشبكة داخلية وبيضمن ترتيب تشغيلهم.
- **حفظ الإعدادات الحساسة برا الكود**: المتغيرات الحساسة (الدومين، الإيميل لشهادة SSL، المنطقة الزمنية) بتنحط بملف `.env` منفصل، مش مكتوبة جوا صورة الـ Docker نفسها.
- **استمرارية البيانات**: بيانات n8n (الـ Workflows، مفتاح التشفير) بتضل محفوظة بـ Volume حتى لو انحذف الـ Container وانعمل من جديد (طالما ما انمسح الـ Volume صراحة).
- **صيانة وتسليم أسهل**: فريق تاني أو شخص تاني بيقدر ياخد نفس ملف الـ Compose ويشغّل نفس البيئة بالضبط، وهاد أساسي لما بدنا "نسلّم" الحل مش بس نجربه على جهازنا.

## 2️⃣ 🎨 Artifact — رسم بنية `compose.yaml` لتشغيل n8n

```
                         compose.yaml
                              │
            ┌─────────────────┴─────────────────┐
            │                                   │
      services: traefik                   services: n8n
      (Reverse Proxy + HTTPS)             (محرك الأتمتة)
            │                                   │
  image: traefik                        image: n8nio/n8n
  ports: "80:80", "443:443"             ports: "127.0.0.1:5678:5678"
  volumes: traefik_data:/letsencrypt    volumes: n8n_data:/home/node/.n8n
  mounts: /var/run/docker.sock (ro)     mounts: ./local-files:/files
  labels: Let's Encrypt (SSL_EMAIL)     environment:
            │                             N8N_HOST, N8N_PORT=5678
            │                             N8N_PROTOCOL=https
            │                             GENERIC_TIMEZONE, TZ
            │                             N8N_WEBHOOK_URL
            │                             NODE_ENV=production
            │                                   │
            └───────────► شبكة داخلية مشتركة ◄───────────┘
                     (Traefik يوجّه الطلبات HTTPS لـ n8n)
                              │
                    top-level: volumes
                 ┌────────────┴────────────┐
            traefik_data                n8n_data
         (شهادات SSL دائمة)         (بيانات وworkflows n8n الدائمة)
```

> 💡 الرسم بيوضح إنه ملف واحد (`compose.yaml`) بيوصف خدمتين مرتبطتين ببعض (Traefik وn8n)، كل وحدة إلها صورتها ومنافذها وتخزينها الخاص، بالإضافة لـ Volumes مشتركة على مستوى الملف كامل تضمن إنه البيانات ما بتضيع لو انعاد تشغيل الـ Containers.

## 4️⃣ 💡 اكتشاف واحد (One Discovery)

Docker Compose مش بس "أداة لتشغيل أكتر من Container مع بعض" — هو فعليًا وثيقة تسليم المشروع. لما كل الإعدادات (الخدمات، المنافذ، التخزين، متغيرات البيئة) موصوفة بملف واحد قابل للمشاركة، أي شخص تاني (أو خادم تاني) بيقدر يعيد بناء نفس البيئة بالضبط من غير ما يعرف كل التفاصيل اللي احنا عرفناها أثناء البناء — وهاد بالضبط الفرق بين "شغّلت المشروع عندي" وبين "سلّمت حل جاهز للتشغيل والصيانة".

## 5️⃣ 🎤 هيكل العرض (Short Pitch — 3 إلى 5 دقائق)

**❓ What?** `compose.yaml` ملف واحد بيوصف كل الخدمات اللازمة لتشغيل n8n (n8n نفسه + Traefik للـ HTTPS) مع منافذها وتخزينها الدائم وإعداداتها.

**💭 Why?** تشغيل Container واحد يدويًا ممكن ينعمل بأمر بسيط، بس تطبيق حقيقي محتاج أكتر من خدمة مرتبطة ببعض، وبدون Compose صعب نضمن إنه نفس الإعداد رح يشتغل بنفس الطريقة على خادم تاني أو بعد فترة.

**⏰ When?** مفيد لما بدنا ننشر n8n على خادم فعلي (مش مجرد تجربة محلية)، وبدنا البيانات تضل محفوظة، والنشر يكون قابل لإعادة التكرار والتسليم لشخص تاني.
